# 数据分析与报告智能体

## 文件

| 文件 | 用途 |
|---|---|
| `talent-analysis-agent.yml` | Dify Chatflow DSL，可直接导入 |
| `talent-analysis-openapi.yml` | 数据分析服务 OpenAPI 定义 |

当前工作流采用“后端注入只读上下文”模式：分析服务先读取看板、梯队、趋势、预测、
模型与报表数据，随 `analysis_context` 一起发送给 Dify；Dify 不再反调本地网关，
因此不需要公网 IP、端口映射、隧道或 `base_url`。

智能体覆盖：

- 人才盘点看板
- 梯队整体健康度、结构、风险、九宫格
- 人才流入、离职、晋升、调岗的历史流动趋势
- 未来 3/6/12 个月流入、流出、晋升预测及置信区间
- 预测结果 CSV 导入导出
- 自定义报表的维度、指标和过滤条件
- 报表生成、存档、历史查询、详情与溯源
- 报表模板查询、保存、删除、一键生成
- 模型训练效果、成功率、AUC、分模型汇总
- 模型训练日志查询、详情和模型名称列表
- 真实训练并部署流失风险、高潜人才、岗位匹配三个模型
- 员工流失风险预测、高潜人才预测和岗位匹配推荐

## 导入

1. 启动 Dify 和后端项目。
2. Dify → 工作室 → 创建应用 → 导入 DSL。
3. 选择 `dify/talent-analysis-agent.yml`。
4. 将 LLM 节点的模型改成 Dify 中已配置的可用模型。
   DSL 默认使用当前环境的 `deepseek-v4-flash`。
5. 检查 Start 节点和工作流环境变量：

```text
Start 输入：query、analysis_context
环境变量：空
```

图中应只有“开始 → LLM → 答案”三个节点。如果还能看到 HTTP Request 节点，说明导入的
仍是旧 DSL。若导入成新应用，应用 API Key 会变化，需要同步更新
`ANALYSIS_DIFY_API_KEY` 后重启分析服务；直接更新现有应用可保留原 Key。

6. 点击发布，然后在“访问 API”中创建该应用自己的 API Key。

工作流不能复用员工档案智能体的 API Key，每个 Dify 应用都有独立密钥。

## 示例问题

```text
分析当前人才梯队健康度
告诉我人才梯队的主要风险和行动建议
分析近两年的入职、离职、晋升和调岗趋势
预测未来 6 个月人才流入、流出和晋升趋势
按部门统计人数、平均绩效、高风险人数和核心骨干人数
按人才标签和流失风险生成报表
生成部门平均年薪报表并保存
列出所有报表模板
使用模板 1 一键生成报表
查看模型运行效果
查询失败的模型训练日志
查看训练日志 1 的完整参数和数据版本
重新训练全部人才模型
预测员工 50 的流失风险
预测员工 1 的高潜等级
给员工 1 推荐 5 个匹配岗位
```

模型推理接口的员工参数支持数字 ID、完整工号和完整姓名，例如
`/api/analysis/model/predict/potential/龙秀英`。

姓名必须与员工档案一致。在线推理未匹配到员工时，助手会直接提示
“未找到”并列出最相近的在职员工，不会把姓名交给大模型猜测推理结果。

## 可部署模型

- `attrition-risk`：人才流失风险预测
- `high-potential`：高潜人才识别
- `position-fit`：岗位匹配度推荐

三个模型使用真实业务数据训练标准化逻辑回归，参数持久化到
`model_artifact`，训练结果写入 `model_log`。模型页面支持单独训练、
全部重训和在线推理。

训练口径：

- 流失风险：以现有“中风险/高风险”为标签，使用司龄、绩效、薪酬系数、
  潜力、技能、培训和年龄特征。
- 高潜人才：以现有 S/A 级为标签，不使用现有潜力总分，改用绩效、职级、
  司龄、技能、培训、薪酬和年龄等业务特征。
- 岗位匹配：员工当前任职岗位作为正样本，同员工的不匹配岗位作为负样本，
  学习核心技能覆盖率、加分技能覆盖率、部门/层级/岗位类型匹配及人才质量。

当前是可复现的基线模型，采用 80/20 随机留出评估，不等同于经过时间外推
验证的正式生产模型。

## 人才流动预测

- 人才流入：基于近 24 个完整月份，使用季节调整线性趋势，并输出 95% 置信区间。
- 人才流出：历史离职事件不足时，使用高风险、中风险和普通在职员工的风险池基线。
- 人才晋升：历史晋升事件不足时，使用高潜人才和储备人才池的业务基线。
- 结果写入 `flow_forecast_run`、`flow_forecast_point` 和 `model_log`，支持 CSV 导入导出。

## 自定义报表

生成报表的请求结构：

```json
{
  "reportName": "部门人才质量报表",
  "dimensions": ["department"],
  "metrics": ["count", "avgPerf", "highRiskCount", "coreTalentCount"],
  "filters": {},
  "save": false
}
```

可用维度：

```text
department, levelTier, position, positionType, potentialLevel,
talentTag, warningLevel, workMode, gender, ageRange, tenureRange, perfLevel
```

可用指标：

```text
count, avgAge, avgTenure, avgSalary, avgPerf, avgPotential,
avgRiskScore, highRiskCount, middleRiskCount, coreTalentCount,
reserveTalentCount, highPotentialCount
```

`save=true` 会把生成结果存档；保存模板使用同一请求结构。

## 当前约束

- 智能体是只读分析链路，不通过 LLM 新增、修改、删除、导入或训练数据。
- 明确的预测、训练和在线推理请求由分析服务在本地执行，不依赖 Dify 回连。
- 流入预测使用历史时间序列；流出和晋升因当前历史事件不足，属于低置信度池基线估算。
- 仪表盘配置导出尚未实现。
- 报表模板目前支持查询、新增、删除和一键生成，没有独立的模板修改接口；修改模板时可先删除旧模板再重新保存。
- 报表模板导入尚未实现。
- 写操作请使用现有管理页面或后端受控接口，并按要求完成权限校验和确认流程。

## 前端接入

数据分析与报告页面底部已经嵌入独立智能体，使用：

```text
GET  /api/analysis/ai/status
POST /api/analysis/ai/chat
```

分析服务通过以下服务端环境变量读取 Dify 应用配置：

```powershell
$env:ANALYSIS_DIFY_BASE_URL="http://127.0.0.1:8080"
$env:ANALYSIS_DIFY_API_KEY="app-数据分析应用密钥"
```

使用 Dify Cloud 时应配置为：

```powershell
$env:ANALYSIS_DIFY_BASE_URL='https://api.dify.ai'
$env:ANALYSIS_DIFY_API_KEY='app-数据分析应用密钥'
```

一键启动脚本会自动从 Windows 用户级环境变量加载这两项配置。数据分析智能体使用
`analysis` 独立会话，不会和员工档案智能体混用对话记录。
