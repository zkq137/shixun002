# 数据分析与报告智能体

## 文件

| 文件 | 用途 |
|---|---|
| `talent-analysis-agent.yml` | Dify Chatflow DSL，可直接导入 |
| `talent-analysis-openapi.yml` | 数据分析服务 OpenAPI 定义 |

智能体覆盖：

- 人才盘点看板
- 梯队整体健康度、结构、风险、九宫格
- 人才流入、离职、晋升、调岗的历史流动趋势
- 自定义报表的维度、指标和过滤条件
- 报表生成、存档、历史查询、详情与溯源
- 报表模板查询、保存、删除、一键生成
- 模型训练效果、成功率、AUC、分模型汇总
- 模型训练日志查询、详情和模型名称列表

## 导入

1. 启动 Dify 和后端项目。
2. Dify → 工作室 → 创建应用 → 导入 DSL。
3. 选择 `dify/talent-analysis-agent.yml`。
4. 将三个 LLM 节点的模型改成 Dify 中已配置的可用模型。
   DSL 默认使用当前环境的 `deepseek-v4-flash`。
5. 检查环境变量：

```text
base_url=http://host.docker.internal:9090
```

如果后端与 Dify 不在同一台机器，改成后端实际网关地址。
本机 Dify Docker 的主机映射与 SSRF 放行配置见 `dify/README.md`。

6. 点击发布，然后在“访问 API”中创建该应用自己的 API Key。

工作流不能复用员工档案智能体的 API Key，每个 Dify 应用都有独立密钥。

## 示例问题

```text
分析当前人才梯队健康度
告诉我人才梯队的主要风险和行动建议
分析近两年的入职、离职、晋升和调岗趋势
按部门统计人数、平均绩效、高风险人数和核心骨干人数
按人才标签和流失风险生成报表
生成部门平均年薪报表并保存
列出所有报表模板
使用模板 1 一键生成报表
查看模型运行效果
查询失败的模型训练日志
查看训练日志 1 的完整参数和数据版本
```

## 自定义报表

生成报表的请求结构：

```json
{
  "reportName": "部门人才质量报表",
  "dimensions": ["department"],
  "metrics": ["count", "avgPerf", "highRiskCount", "coreTalentCount"],
  "filters": {},
  "save": false
}
```

可用维度：

```text
department, levelTier, position, positionType, potentialLevel,
talentTag, warningLevel, workMode, gender, ageRange, tenureRange, perfLevel
```

可用指标：

```text
count, avgAge, avgTenure, avgSalary, avgPerf, avgPotential,
avgRiskScore, highRiskCount, middleRiskCount, coreTalentCount,
reserveTalentCount, highPotentialCount
```

`save=true` 会把生成结果存档；保存模板使用同一请求结构。

## 当前约束

- 后端目前提供人才流动的**历史趋势**，没有训练好的流入/流出/晋升预测接口，也没有预测数据导入导出接口。智能体会明确说明这是历史观察或情景判断，不会伪造预测值。
- 仪表盘配置导出尚未实现。
- 报表模板目前支持查询、新增、删除和一键生成，没有独立的模板修改接口；修改模板时可先删除旧模板再重新保存。
- 报表模板导入尚未实现。
- 删除报表或模板必须明确回复“确认删除”。

## 前端接入

数据分析与报告页面底部已经嵌入独立智能体，使用：

```text
GET  /api/analysis/ai/status
POST /api/analysis/ai/chat
```

分析服务通过以下服务端环境变量读取 Dify 应用配置：

```powershell
$env:ANALYSIS_DIFY_BASE_URL="http://127.0.0.1:8080"
$env:ANALYSIS_DIFY_API_KEY="app-数据分析应用密钥"
```

一键启动脚本会自动从 Windows 用户级环境变量加载这两项配置。数据分析智能体使用
`analysis` 独立会话，不会和员工档案智能体混用对话记录。
